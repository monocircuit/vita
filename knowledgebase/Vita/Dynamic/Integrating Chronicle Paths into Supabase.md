### Why even save Chronicle Paths?
A [[DynamicVita]] stores more information than a basic [[StaticVita]] (a normal CV), it connects the resume entries ([[Chronicle]]) together like a graph, this information needs to be stored somehow somewhere.

It would also be a thought, to try to not even store this information at all, but this would make personalizing and tweaking the [[DynamicVita]] impossible. This way the [[Vita]] would need to be autogenerated on every reload of the page with a standardized algorithm that does not account for nor remember any changes to the [[Vita]] the user made.

For saving this information, it is important to note, that the Chronicles are not exactly connected like a graph.

### Why the old Chronicle Relations do not work efficiently and make life harder going on
The current implementation of trying to store this additional information I talked about earlier, tries to make connections between the [[Chronicle|Chronicles]]. This is in itself a wrong attempt. A [[Chronicle]] might end at any time and another [[Chronicle]] has to make a [[TakeOver]]. The [[Chronicle]] that took over the previous one is now not connected to the previous one anymore. Thus it would make no sense to have a connection between these two.

What I am trying to say is, that the current implementation makes such [[Maneuvers]] quite difficult to implement, another data structure might do this more easily and elegantly.

### Benefits that come with using [[ChroniclePath|ChroniclePaths]]
Using [[ChroniclePath|ChroniclePaths]] will make pushing changes to the [[DynamicVita]] way easier, as the data structure itself is way more simple and does not require complex rewiring.

### `vita_dynamic_paths`
This will be the table to store all [[ChroniclePath|ChroniclePaths]] needed to display a [[DynamicVita]] according to the wishes and tweaks of the user.
